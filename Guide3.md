# GUIDE 3 — CONTENT, INTERACTION & EXPERIENCE SPECIFICATION
## Harry Jees — Interactive Cinematic Portfolio

---

# 1. PURPOSE OF THIS GUIDE

This guide defines the content presentation, interaction behavior, visual storytelling, and experience requirements for the Harry Jees portfolio.

This is NOT intended to be a conventional portfolio website.

The website should feel like an interactive cinematic experience where scrolling is the primary method of navigation and every major section responds to the visitor's movement.

The visitor should feel as if they are moving through a carefully designed digital environment rather than scrolling through a collection of static webpage sections.

The experience should be:

- Cinematic
- Interactive
- Minimal
- Technical
- Human
- Premium
- Natural
- Responsive
- High contrast
- Visually memorable

The website must avoid feeling like an AI-generated template.

---

# 2. CORE EXPERIENCE PRINCIPLE

The most important principle is:

## Vertical scrolling is the INPUT, not necessarily the visual movement.

The user scrolls vertically.

The website can respond by:

- Moving horizontally
- Moving diagonally
- Moving through depth
- Changing camera position
- Scaling objects
- Pinning scenes
- Revealing content
- Transitioning between environments
- Progressing through timelines
- Changing focus between content items

Therefore, the entire website should NOT simply behave like:

Section 1
↓
Section 2
↓
Section 3
↓
Section 4

Instead, scrolling should control a cinematic sequence.

---

# 3. PACING

The experience must never feel rushed.

Every important visual state should remain on screen long enough for the visitor to:

- Notice it
- Understand it
- Read it
- Appreciate it
- Then move on

Avoid extremely short animation durations.

Avoid transitions that happen immediately when the user scrolls a few pixels.

Major sections should have enough scroll distance to establish themselves.

The visitor should feel in control.

Do not use aggressive snapping unless absolutely necessary.

---

# 4. NATURAL DESIGN PRINCIPLE

The website should feel designed by a human rather than generated by an AI.

Avoid unnecessary visual decoration.

Do NOT add:

- Random images
- Random SVGs
- Decorative blobs
- Random floating cards
- Generic AI illustrations
- Excessive gradients
- Excessive glassmorphism
- Random glowing objects
- Unnecessary 3D objects
- Decorative elements without meaning

Every visual element should have a purpose.

If an element does not contribute to:

- storytelling
- navigation
- identity
- information
- interaction
- atmosphere

remove it.

---

# 5. TYPOGRAPHY

Typography should create a strong hierarchy.

Primary headings should be visually dominant.

Secondary text should be smaller but still clearly readable.

Do NOT use extremely low-opacity gray text.

Do NOT make secondary content so faint that users have difficulty reading it.

The visual hierarchy should generally be:

PRIMARY
→ strongest

SECONDARY
→ clearly visible but quieter

SUPPORTING
→ subtle but readable

Avoid making every piece of text pure white.

Use contrast through:

- size
- weight
- spacing
- opacity
- positioning

rather than simply making everything brighter.

---

# 7. HERO PARTICLE PORTRAIT

The Hero contains the primary particle experience.

The particles should form Harry Jees' portrait.

Sequence:

1. Particles appear
2. Particles begin gathering
3. Portrait gradually forms
4. Portrait becomes recognizable
5. Portrait holds
6. Subtle movement occurs
7. Portrait rotates subtly
8. Particle structure destabilizes
9. Particles explode outward
10. Particles spread through 3D space
11. Particles slow
12. Hero scene ends

The portrait must remain visible long enough to appreciate.

The particle explosion should not happen immediately.

The movement should feel cinematic rather than like a simple particle animation.

---

# 8. HERO PARTICLE LIFECYCLE

The Hero particle system is independent.

It does NOT need to continue through the entire website.

The lifecycle can be:

FORM
→ HOLD
→ ROTATE
→ EXPLODE
→ DISSIPATE
→ END

Do not create a technically unnecessary persistent particle system connecting every section.

Later sections can use their own independent visual systems.

This keeps the implementation:

- More reliable
- More performant
- Easier to control
- Easier to debug

The camera should contribute to the cinematic feeling.

Possible progression:

# 38. ANIMATION RESPONSIBILITY

Major scroll animations should be controlled by:

GSAP + ScrollTrigger

3D environments:

Three.js / React Three Fiber

Camera choreography:

Theatre.js where useful

Smooth scrolling:

Lenis

Micro-interactions:

Anime.js

Do not let multiple animation libraries control the same major movement.

---

# 39. ANIME.JS

Anime.js should NOT replace GSAP.

Anime.js is for small details.

Good uses:

- underline drawing
- tiny text animations
- small SVG path animation
- hover details
- subtle UI state transitions
- small decorative motion with meaning

Bad uses:

- global scroll
- section pinning
- project progression
- camera movement
- major 3D animation

---

# 40. GSAP SCROLLTRIGGER

GSAP ScrollTrigger is responsible for the cinematic scroll structure.

Use it for:

- pinning
- scrubbing
- horizontal movement
- section progression
- project transitions
- capability progression
- journey progression
- topic focus

The scroll system must be reliable.

---

# 41. PINNING REQUIREMENT

Pinned scenes are a CORE requirement.

A section that is intended to be cinematic must actually remain on screen while the visitor scrolls through its sequence.

Do NOT fake this using simple CSS animations.

Verify:

- pin works
- pin duration is sufficient
- horizontal movement happens while pinned
- next section does not immediately cover it
- smooth scrolling does not break pinning
- ScrollTrigger refreshes correctly
- responsive layouts do not break pinning

---

# 42. SMOOTH SCROLLING

Scrolling should feel smooth and cinematic.

Use one global smooth-scroll system.

Avoid:

- multiple scrolling engines
- competing wheel listeners
- duplicate requestAnimationFrame loops
- scroll-jacking that makes the site difficult to use

The user should feel that scrolling is fluid rather than delayed or broken.

---

# 43. RESPONSIVENESS

The experience must work across:

- Desktop
- Tablet
- Mobile

Do not simply scale the desktop website down.

Mobile may require simplified versions of:

- particle effects
- networks
- camera movement
- horizontal scenes
- transitions

The content and experience must remain understandable.

---

# 44. MOBILE SCROLLING

Do not trap users in horizontal scrolling.

Vertical scrolling should remain the natural input.

Horizontal cinematic movement can happen as a response to vertical scroll.

Avoid horizontal overflow.

---

# 45. ACCESSIBILITY

Animation should enhance the experience, not make the website unusable.

Ensure:

- text remains readable
- links are keyboard accessible
- focus states are visible
- project information remains understandable
- capability information remains understandable
- topic information remains understandable

Respect:

`prefers-reduced-motion`

When reduced motion is enabled:

- reduce camera movement
- reduce particle movement
- reduce parallax
- simplify transitions

Do not remove essential content.

---

# 46. PERFORMANCE

The portfolio contains WebGL and scroll animation.

Performance must therefore be considered from the beginning.

Use:

- efficient particle systems
- limited particle counts
- GPU-friendly geometry
- lazy activation of scenes
- disposal of unused resources
- cleanup of animation instances
- cleanup of ScrollTriggers
- cleanup of event listeners

Do not keep every 3D environment active simultaneously.

---

Each major WebGL scene should be independently manageable.

Hero particles:

Independent

Independent

Journey visual:

# 48. NO UNNECESSARY DECORATION

The portfolio should have visual restraint.

Do not add something merely because there is empty space.

Empty space is allowed.

In fact, negative space should be used intentionally.

A minimal scene with one strong visual is better than a scene containing ten weak visuals.

Do not make supporting content invisible.

# 51. FINAL EXPERIENCE RULE

The website should not feel like:

"Here is my portfolio."

It should feel like:

"This is an interactive journey through how Harry thinks, builds, learns, shares, and creates."

The visitor should remember the experience.

But the experience must remain usable.

Cinematic does NOT mean:

- excessive effects
- constant motion
- random 3D
- overwhelming particles
- complicated navigation

Cinematic means:

- intentional pacing
- controlled camera movement
- meaningful transitions
- strong composition
- spatial storytelling
- visual continuity
- restraint

---

# 52. MOST IMPORTANT IMPLEMENTATION RULE

Do not sacrifice stability for visual effects.

The priority order is:

1. Correct content
2. Correct structure
3. Correct scroll behavior
4. Correct pinning
5. Correct responsiveness
6. Correct animation timing
7. 3D/WebGL polish
8. Micro-interactions

Never reverse this order.

A beautiful animation that breaks scrolling is worse than a simpler animation that works perfectly.
